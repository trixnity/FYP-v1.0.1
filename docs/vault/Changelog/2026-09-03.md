## Payments: real gateway sandbox + tax-grade receipts

### Context
Stripe Checkout redirect was already wired (`payNow()` → `POST /{id}/checkout` →
`window.location = session.url`). It "didn't work" only because `STRIPE_SECRET_KEY`
resolves to empty in both profiles → `Stripe.apiKey = ""`. No new gateway needed;
Stripe **test mode** is the sandbox.

### Security fix (the important one)
`POST /api/payments/{id}/pay` (`markPaidManually`) let **any student mark their own
payment PAID for free** and activate the plan. Now **ADMIN-only** ("record off-gateway
payment"). The student UI never called it, so no UI breakage.

### Built
- **Webhook** `POST /api/payments/webhook` — `Webhook.constructEvent` signature check,
  handles `checkout.session.completed` + `checkout.session.async_payment_succeeded`.
  Public in `SecurityConfig` (POST). New `STRIPE_WEBHOOK_SECRET`. Signature verify +
  event parse live in `PaymentService` (no DB work) so the controller calls the
  `@Transactional` confirm method through the Spring proxy (avoids self-invocation).
- **Idempotency** — `markPaidFromCheckoutSession` / `markPaidManually` return early if
  already PAID. Redirect + webhook both safe.
- **Receipt number** — `Payment.receiptNumber` (`@Column(unique)`), format
  `EDU-<year>-<6-digit id>`, assigned once at confirmation. Legacy PAID rows get one
  lazily via `PaymentService.ensureReceiptNumber` on first receipt request.
- **Payment method** — `Payment.paymentMethod`, resolved from the Stripe PaymentIntent →
  latest Charge (card brand+last4, or FPX bank). Best-effort, never fails the payment.
- **Receipt PDF rewrite** (`PaymentReportService`) — issuer block from `RECEIPT_ISSUER_*`
  config, "OFFICIAL RECEIPT" + number + dates, itemised line, subtotal/tax/total,
  payment method, gateway ref, optional `RECEIPT_TAX_NOTE`, "computer-generated" footer.
  PAID-only guard on both `/receipt` and `/receipt/pdf` (409 otherwise).
- **Frontend** — receipt modal shows Receipt no. + Payment method + gateway ref;
  `?payment=success|failed|cancelled` on the dashboard now shows a message and opens
  My Payments, then cleans the URL.
- **Config/docs** — `stripe.webhook-secret` + `receipt.*` in both properties files;
  `DEPLOYMENT.md §0.6` (Stripe keys, webhook setup, test card, FPX, `stripe listen`).

### Deliberately NOT done (per advisor)
- No gateway swap (Billplz/ToyyibPay) — code is Stripe, Stripe covers MY (cards + FPX).
- No MyInvois/LHDN e-Invoice integration — documented as a limitation; PDF is a
  conventional official receipt, not a validated e-Invoice.
- No email delivery of receipts.
- `receipt.tax-note` is free text the issuer supplies — system does not verify tax
  deductibility (no deductibility claims baked into the PDF).

### Verified
- `./mvnw -q -B -DskipTests compile` → exit 0 (Stripe 33.1.0 API surface confirmed:
  `Webhook`, `PaymentIntent.getLatestCharge`, `Charge.PaymentMethodDetails` card/fpx).
- **Not run:** full Checkout flow (needs a real `sk_test_` key + running MySQL + browser).
